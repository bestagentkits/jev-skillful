Skillful

A capability router for coding agents. It watches your prompts, decides whether a skill, MCP server, subagent or command you already installed is relevant, and injects at most one suggestion. 

npx @mrgoonie/skillful install

You bring your own TYPESAFE_API_KEY. There is no server, no account, and nothing is collected. The only network call Skillful makes is the routing request to api.typesafe.ai.

Why this exists

The usual way to make an agent aware of a skill is to list every skill in the context window. That does not scale. The paper Skill Retrieval Augmentation for Agentic AI found that as a skill corpus grows, context budget is consumed quickly and the agent becomes less accurate at picking the right skill. The same work found agents load skills at a similar rate whether or not the task needs one, so the problem is both which capability and whether to load one.

A development machine here has around 230 skills across two runtimes, plus MCP servers, subagents and commands.

How it works

A local scan builds a shortlist of about fifteen candidates with BM25 and per-kind quotas, with no tokens spent. One TypeSafe request then asks a single choice question over that shortlist plus none. At most one primary suggestion and two runner-ups are injected, and a prompt that needs nothing gets nothing.

The shortlist is what the model sees, not what gets injected. Injecting all fifteen would reproduce the exact pattern that made retrieval necessary.

What is measured

Routing quality is measured against 67 development fixtures and 22 holdout fixtures over a 533-entry corpus:

Metric Result Target
recall@K (development) 0.824 0.90
recall@K (holdout) 0.600 0.90
top1Accuracy 0.731 0.80
noneF1 0.813 0.80
agreement rate 0.985 0.90
p95 route latency 406ms 1500ms

The target is not met, and the gap is not a tuning problem

Recall depends only on the shortlist, which BM25 and the quotas build entirely, so it can be swept with no API calls. Growing the shortlist from 13 entries to 21 raised recall from 0.600 to 0.650. It saturates because BM25 matches tokens: it finds a capability only when a prompt happens to share vocabulary with a capability description, and prompts are phrased as tasks while descriptions are phrased as capability statements. Closing the gap needs a different retrieval stage, not a different parameter.

The outcome benchmark does not exist yet. Whether injecting a suggestion makes an agent complete a task better is the question that matters, and it is not answered. Until it is, this project claims a routing improvement and makes no claim about task outcomes.

What it does reliably

  • Installs for Claude Code, Codex, Pi and OMP, idempotently, with a timestamped backup before any file is modified, and removes exactly what it added.
  • Leaves other tools' hooks untouched.
  • Fails open. A missing key, dead network, upstream error or expired budget each inject one reminder line and exit 0. Nothing is written to stderr.
  • A cold route took 1446ms against a 2000ms budget; a repeated prompt hit the cache in 221ms.

Commands

npx @mrgoonie/skillful install       # install the hook for every runtime present
npx @mrgoonie/skillful doctor        # is it working? includes a live trial route
npx @mrgoonie/skillful uninstall     # remove it, leaving other hooks alone

npx @mrgoonie/skillful catalog --summary        # what was found
npx @mrgoonie/skillful route --prompt "..." --explain
npx @mrgoonie/skillful eval --recall-only       # offline quota sweep, no key, no cost
npx @mrgoonie/skillful export-case --prompt "..."  # redacted case for a bug report
